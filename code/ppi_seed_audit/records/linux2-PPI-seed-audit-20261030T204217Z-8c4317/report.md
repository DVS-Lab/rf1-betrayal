# Original PPI seed provenance audit

No analysis was rerun or modified. Original L3 → L2 → L1 links, saved physiological custom EV paths, full saved FSFs/model matrices and small timecourse files are indexed here. The scan covers original project N132 group outputs and original insula-like PPI directories for manuscript participants; accepted/excluded runs remain explicitly marked. Current and Git-historical scripts plus source log excerpts are evidence, not proof that a filename was used in a particular run.

physiological_EVs.json checks both FEAT custom_timing_files/evN.txt snapshots and current external series against the actual saved design column when direct unfiltered physiological-EV processing supports an affine comparison. Cached snapshots take priority for numerical reconstruction, while external-versus-cache differences remain recorded. Mismatch can indicate an overwritten source; unsupported processing is left unresolved. A numerical candidate match is strongest when both current original-BOLD mean extraction and saved-design membership agree. Only exact FSF-referenced BOLD paths are used, never regenerated substitutes. Candidate masks must share the exact voxel lattice; field-of-view embedding preserves voxel centers without interpolation. Binary/integer mask means are computed with float64 accumulation in a single serial 4D read per selected original image. The sample is selected by task/seed family before numerical matching, with at most 4 original BOLD images. Missing BOLD, equivalent mask supports, stale external series, or lack of contemporaneous extraction logs may prevent an exact historical seed-file attribution.

source_manifest.json maps original paths/Git commits to exact content-addressed members of split source-files-*.tar.gz archives. Archives contain small text/model sources and 3D mask candidates, never participant 4D images. candidate_timecourse_comparisons.json records raw and affine agreements separately; raw numerical agreement alone does not prove historical filename identity. Use analysis_chain.json to identify which L1 seed variants actually feed saved group analyses, rather than assuming every directory was used.
