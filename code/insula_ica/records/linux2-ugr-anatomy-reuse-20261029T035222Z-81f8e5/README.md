# Automated UGR anatomy reuse and unsmoothed FEAT recovery

A single-run and a two-run participant form the pilot. Each accepted run has an isolated read-only BIDS view, unchanged stock query JSON, anatomy-only derivative cache, and separate work/output tree. The pilot must pass installed-container anatomy-graph checks, actual normalization-reuse log checks, BOLD grid/time/TR/finiteness, correct-run reference evidence, minimum 80% left/right/bilateral insula coverage, historical reference spatial correlation >=0.90, and the original joint FEAT design/contrast/nuisance identity checks at zero smoothing before automatic expansion. These pilot thresholds gate expansion, not participant exclusion. Full-cohort QC flags remain available for scientific review. Historical voxelwise equality is not required.

Up to 32 subject workers run fMRIPrep (8 threads / 4 OpenMP / 12,000 MB each), and up to 64 workers run FEAT. Both share a CPU and available-memory gate with 12 GiB headroom; queue limits are not promises of simultaneous execution. No anatomy normalization, TEDANA fitting, Warpkit fitting, original sm-5 FEAT, or ICA is requested. Regenerated UGR BOLD overrides are explicit and identity checked. Existing completed Trust sm-0 fits are reused. The combined sm-0 record is published after recovery and validates all 490 accepted FEATs. See state.json, raw-warpkit-audit.json, cases/, qc/, ugr-feat/qc/, and errors/.
